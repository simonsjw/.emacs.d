* Getting started with this tree

This repository is Simon Watson's Emacs 30 configuration.  It is not a
Crafted Emacs clone to drop into an empty =.emacs.d=.  The checkout
*is* the configuration.

** Layout on disk

On the primary machines, =~/.emacs.d= is a symlink to this tree (for
example under =~/sync/primary/emacs/.emacs.d=).  That path is
~user-emacs-directory~.

Machine-local *state* lives under =var/$MY_NAME/=.  Machine-local
*configuration* (including =custom.el= and the native-comp cache) lives
under =etc/$MY_NAME/=.  First-party Lisp lives under =custom-modules/=;
local packages live under =custom-packages/=.

** Emacs version

Target Emacs is *30.1 or newer*, built with native compilation,
Tree-sitter, and HarfBuzz.  On these machines the binary is
=/usr/local/bin/emacs=.

** How to launch

Do not start a bare ~emacs --fg-daemon~ for day-to-day use.  Launch via
=emacs-daemon-wrapper= (adjacent repo
https://github.com/simonsjw/emacs-daemon-wrapper), then connect with
~emacsclient~.

The wrapper sources login shell files, sets Wayland Qt/GDK hints,
re-asserts ~SSH_AUTH_SOCK~, and execs Emacs as a foreground daemon.
Optional: point a systemd ~--user~ unit ~ExecStart=~ at the wrapper.

Detail for install paths and related OS tools belongs in
=docs/os-integrations.org= (and the tables in =conf.org=).

** Required environment variables

Export these from the login shell (=~/.bashrc= / =~/.bash_profile=) before
the daemon starts.  Examples and the full table live in =conf.org=;
the narrative catalog is =docs/os-integrations.org=.

| Variable | Role |
|----------|------|
| ~MY_NAME~ | Per-machine namespace under =var/= and =etc/= (default ~INFODYNAMICS~) |
| ~USER_EMACS_DIRECTORY~ | Config root (this tree) |
| ~ENV_FILE~ | Extra ~KEY=value~ dump loaded at startup |
| ~BIB_HOME~ | Default bibliography path |
| ~REPO_LIST~ | CSV of known git repos |
| ~PROJECT_PATHS~ | Comma-separated ~dir:depth~ search roots (documented name; see =conf.org=) |

Also keep ~PATH~, Conda (~CONDA_PREFIX~, ~WORKON_HOME~), and API keys in
~$ENV_FILE~ as needed for language servers and LLM tools.

** Literate configuration

=conf.org= is the source of truth for =early-init.el= and =init.el=.
Edit =conf.org=, then save so Org tangles the Lisp files.  Do not treat
the tangled =init.el= as primary source.

Every ~(require …)~ that boots a first-party module is visible in the
=conf.org= tangle block.  Module inventory and purpose live in
=docs/MAP.org=, not as a second require list.

** Where agents (and humans) should look

Read order for any change to this tree:

1. =AGENTS.md= at the repo root (short pointer).
2. =docs/MAP.org= (feature, file, phase, depends, keymaps, docs, purpose).
3. The module named in that row, plus =docs/<feature>.org=.
4. =conf.org= only when startup, environment variables, or OS
   dependencies change.
5. =custom-modules/keymaps/= only when the module's Commentary ~Map:~
   block names a keymap file.

Feature name equals filename stem equals ~(provide 'feature)~.  After
adding or renaming a feature, update =docs/MAP.org= in the same change.

** Building the Info manual

From =docs/=:

#+begin_src shell
  make docs
#+end_src

That runs =my-docs.el= and writes the Info manual for this tree.  Prefer
~make docs~ over interactive ~org-export-dispatch~.  Markup and
contribution notes are in =docs/CONTRIBUTING.org=.

** What not to commit

Do not commit machine-local state or caches from this tree, including:

- =var/$MY_NAME/= dumps (backups, undo, elpa state, project lists, …)
- =etc/$MY_NAME/custom.el=
- =eln-cache/= / =etc/$MY_NAME/eln-cache/=
- =init.log= / =init.log.bak=
- Secret-shaped env dumps such as =serviceEnv.txt=

See =.gitignore= for the patterns already ignored.  Keep secrets in
~$ENV_FILE~ outside the repo.
